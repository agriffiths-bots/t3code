# DSEG slice 7 round 7: runtime-event binding plan

Intent: Restore runtime-event projection by treating the server-stamped thread id as the lookup key into the live provider-session registry. Every runtime consumer will accept an event only when that direct binding exists and its provider target matches, then derive the projection thread/audience and session identity from the binding without turn-id correlation or single-session fallback.

Blast radius: `providerRuntimeEventProvenance.ts` and both production stream subscribers (`ProviderRuntimeIngestion.ts`, `CheckpointReactor.ts`); runtime-event metrics; their integration harnesses and previously disabled restoration tests. The class sweep also covers `ProviderService.ts` (adapter-source provider/instance correlation, persisted-binding state writes, canonical publication), all adapter session registries/stampers (Codex, OpenCode, Claude, Cursor, Grok/ACP), projection/read-model audience resolution, late/replayed event ordering, checkpoint capture, and restart/session-removal behavior; no contract, envelope, persistence schema, client, migration, or command-audience changes are needed.

## Edge-case matrix and red-first proof

| Edge/order                                                                                                            | Expected invariant                                                                        | Named red-first test                                                                                      |
| --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `content.delta` then trailing `turn.completed` after turn T is already terminal, with 2 live sessions on one instance | Both project to T from T's direct thread binding                                          | `projects trailing delta and completion after terminal state with multiple live sessions`                 |
| Same trailing pair after T+1 becomes active, with 2 live sessions on one instance                                     | T output/completion project without closing or rebinding T+1                              | `projects old-turn trailing events after a later turn starts with multiple live sessions`                 |
| Claimed provider/instance disagrees with the binding, including lifecycle events                                      | Drop before projection/checkpoint work and emit greppable `target-mismatch` audit outcome | `drops a spoofed bound-thread target and emits a target-mismatch audit` plus checkpoint mismatch coverage |
| No live binding (session ended/restart race)                                                                          | Drop fail-closed and increment the binding-drop counter with `no-binding`                 | `drops an unbound runtime event and increments the no-binding counter`                                    |
| Duplicate/replayed terminal and late-delta order both ways                                                            | Existing idempotency/terminal caches retain one finalized assistant projection            | Re-enabled Cursor terminal-ordering and duplicate-completion restoration tests                            |
| Same timestamp events and concurrent sessions sharing one instance                                                    | Thread-id lookup, not time/list order/turn match, selects authority deterministically     | Both mandatory multi-session tests use identical timestamps and explicit old/new turns                    |
| Crash between event publication and consumption / binding removal                                                     | A missing live binding cannot project after restart/removal                               | No-binding counter test; lookup occurs inside each consumer immediately before work                       |
| Legacy/version-skewed missing instance identity                                                                       | Exact target equality fails closed instead of treating absence as a wildcard              | `drops an event with missing instance identity in both runtime consumers`                                 |

Smallest change: replace the unconditional provenance gate with one shared binding resolver and call it at the top of each existing consumer. Keep event payload mapping and lifecycle ordering intact, change only target/audience/session identity reads to the resolved binding, add one counter, and reactivate the retained runtime restoration tests; do not add an envelope field or any turn/source derivation stage.
