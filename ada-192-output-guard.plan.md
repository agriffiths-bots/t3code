# ADA-192 provider output-preservation guard plan

## Intent

Restore the localized cross-adapter completion guard removed by PR #214's tests-only split, then close the three mapped ownership holes that remained in its final pre-split implementation. An owned successful turn will fail closed only after every provider-specific output path is provably exhausted, while stale, recovered, duplicate, restarted, or late-output paths remain fail-open toward preserving real output.

## Diagnosis and proof baseline

Commit `cdd1fb8e9` removed the guard from `ProviderService.ts` and skip-tagged its four assertions while leaving the broader ordering and adapter-output matrix in place. The removed implementation shows the exact causal chain behind #217: an owned output-free `turn.completed` currently reaches ingestion unchanged, so the projected session records a successful terminal turn with `lastError: null`; it also shows that a duplicate completion loses ownership after the first terminal persist, a live same-service Cursor restart was treated like crash recovery, and grace-buffer replay recomputed rather than carried the ownership already proved at ingress.

## Blast radius

- `apps/server/src/provider/Layers/ProviderService.ts`: canonical event classification, per-adapter/instance/thread/turn output tracking, active-turn ownership persistence, Cursor late-delta buffering, session recovery, adapter-generation replacement, event publication, logging, and metrics.
- `apps/server/src/provider/Layers/ProviderService.test.ts`: focused state-machine, ordering, restart, duplicate/replay, adapter-shape, and mutation coverage for Codex, Claude Agent, Grok, Cursor, and the generic adapter path (including OpenCode by canonical shape).
- `apps/server/src/provider/Layers/providerFailureMessages.ts`: named shared empty-response and watchdog messages used by production and tests without copied literals.
- `apps/server/src/provider/Layers/ProviderSessionReaper.ts` and `.test.ts`: watchdog terminal reasons only; behavior remains unchanged while message construction becomes shared.
- `apps/server/src/orchestration/Layers/ProviderRuntimeIngestion.test.ts`: re-enable the recorded empty Codex E2E and assert the shared empty-response message survives projection; no ingestion production change.
- Downstream consumers at risk are `ProviderRuntimeIngestion`, thread/session projections (`lastError`, latest-turn state), `ProviderSessionReaper`, `ChildThreadCoordinator` lease/wake settlement, canonical NDJSON logging, metrics, and restart/resume callers. No contracts, schemas, persisted payload shape, migration, adapter API, client, or UI changes are planned.

Ordering is asserted in both directions (output before completion and Cursor output after completion). Duplicate/replay coverage includes starts and completions; crash-between-steps is represented by ProviderService rebuild/recovery; same-timestamp events remain source ordered; version skew is fail-safe because recovered active-turn history is inconclusive; and concurrent ingress during a grace drain is identity-rechecked before buffer append. Provider instance, adapter generation, thread, and turn keys prevent cross-session contamination.

## Smallest-change argument

Reapply the already-reviewed local guard machinery from the last pre-split implementation, adapt it to current `main`, and add only persisted/ephemeral classification needed for the three explicitly mapped residual holes. Reuse the existing persisted `activeTurnId` / `lastTerminalTurnId`, adapter-generation identity, and fixed Cursor grace boundary; do not add a protocol field, database state, adapter capability, watcher, or new orchestration mechanism. If correctness requires any schema/API redesign or expansion beyond these files, stop with the safe proven subset as required by the scope cap.
