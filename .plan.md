# ADA-111 Claude Steer-Abort Classification Plan

## Intent

Fix the false failed-turn/error-banner classification that can follow a successfully delivered
mid-turn Claude steer. Treat only the Claude SDK's known non-error user-steer abort result as an
interruption, while preserving failure handling for genuine `error_during_execution` results.
Suppress the fork's ADA-79 retry banner only for that diagnostic because resending an already
delivered steer risks duplicate work.

The 2026-07-10 provenance verdict is the scope boundary: delivery and steering already work. This
change adds no queueing, retry, deduplication, persistence, or crash-recovery machinery.

## Blast radius

- `apps/server/src/provider/Layers/ClaudeAdapter.ts`
  - Extend the existing `isInterruptedResult` decision with a conservative predicate requiring
    `subtype=error_during_execution`, `is_error=false`, `[ede_diagnostic]`, `result_type=user`, and
    a known steer-abort marker (`stop_reason=tool_use` or `turn aborted`).
  - Reuse the existing interrupted completion path, which avoids `runtime.error` and
    `session.lastError`; do not alter provider delivery or session lifecycle code.
- `apps/server/src/provider/Layers/ClaudeAdapter.test.ts`
  - Add red-first exact-envelope coverage for the tool-use and turn-aborted shapes.
  - Add negative controls proving ordinary execution failures and near-miss diagnostics remain
    failed, emit `runtime.error`, and record `session.lastError`.
- `packages/client-runtime/src/errors/transport.ts`
  - Suppress the exact user-steer diagnostic before the broader ADA-79 friendly-copy mapping.
  - Preserve current behavior for explicit request aborts, non-user diagnostics, transport errors,
    and unrelated application errors.
- `packages/client-runtime/src/errors/transport.test.ts`
  - Add red-first no-banner coverage plus marker/result-type near misses.
- Runtime verification
  - Rebuild desktop artifacts and drive a real Claude turn on a disposable server. Send a second
    message mid-turn and verify delivery, continued work, a non-failed turn, and no banner.
  - Never restart or deploy the live server.

## Edge-case matrix

| Case                                 | Input                                                                                                                                     | Expected                                                                     |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Tool-boundary user steer             | `error_during_execution`, `is_error=false`, one diagnostic line containing `[ede_diagnostic]`, `result_type=user`, `stop_reason=tool_use` | Interrupted completion; no `runtime.error`; no `lastError`; no client banner |
| Turn-aborted user steer              | Same subtype/flag/diagnostic identity plus `turn aborted`                                                                                 | Same clean interrupted classification and no banner                          |
| Token order/case varies              | Required tokens remain on the same diagnostic line                                                                                        | Still matches                                                                |
| `is_error=true` near miss            | Otherwise identical diagnostic                                                                                                            | Failed; visible error remains                                                |
| Non-user diagnostic                  | `result_type=assistant` with a known abort marker                                                                                         | Failed server result; client does not take the new suppression branch        |
| User diagnostic without abort marker | `[ede_diagnostic] result_type=user status=failed`                                                                                         | Failed and preserved                                                         |
| Generic execution failure            | Ordinary `error_during_execution` error text                                                                                              | `runtime.error`, failed completion, and `lastError` remain                   |
| Existing explicit abort              | `Error: Request was aborted.`                                                                                                             | Existing interrupted classification and ADA-79 friendly copy remain          |
| Transport failure                    | Existing socket/ping pattern                                                                                                              | Still sanitizes to `null`                                                    |
| Unrelated business error             | Missing credential or invalid selection                                                                                                   | Preserved verbatim                                                           |
| Old server / new client              | Exact raw steer diagnostic reaches the sanitizer                                                                                          | Hidden to avoid unsafe retry advice                                          |
| New server / old client              | Server emits interrupted rather than failed state                                                                                         | No runtime/session failure state; no new contract required                   |

## Red-first test plan

1. Change only tests and run the two affected suites on old production code.
   - Server exact SDK result: assert no `runtime.error`, interrupted completion, ready session, and
     no `lastError`. Expected RED: old code emits `runtime.error`, completes failed, and records the
     diagnostic.
   - Server genuine failure: assert the old failed path remains green.
   - Client exact diagnostic: assert `sanitizeThreadErrorMessage(...) === null`. Expected RED: old
     code returns `The turn was interrupted. Send your message again to retry.`
   - Add near-miss controls for `is_error=true`, non-user diagnostics, and missing abort markers.
2. Record the RED output, then implement the two minimal predicates and rerun targeted suites:
   - `vp test apps/server/src/provider/Layers/ClaudeAdapter.test.ts`
   - `vp test packages/client-runtime/src/errors/transport.test.ts`
3. Run repository requirements:
   - `vp check`
   - `vp run typecheck`
4. Run `vp run build:desktop`, then verify with a fresh disposable `ada-111-verify` instance and a
   real Claude turn. Capture screenshots plus server/projection evidence and tear the instance down.
5. Commit implementation through the factory gate, open a draft PR whose body includes
   `Fixes ADA-111`, mark ready once, wait deterministically for Codex, babysit CI/review, and land
   only through `wizzo-approve`.

## Smallest-change argument

The defect is a classification mismatch at an existing SDK result boundary. A narrow predicate in
`isInterruptedResult` reuses all existing clean-interruption control flow. A matching client-side
predicate with an early `null` return removes only the unsafe retry advice. No protocol, schema,
delivery, orchestration, or UI-component change is needed. The negative controls keep genuine
execution failures fail-closed and visible.
