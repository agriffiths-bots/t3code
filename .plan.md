# ADA-111 Claude Steer-Abort Classification Plan

## Intent

Fix the false failed-turn/error-banner classification that follows a successfully delivered
mid-turn Claude steer. Treat only the Claude SDK's known user-steer abort result shapes as
interrupted/clean, while preserving failure handling for genuine `error_during_execution` results.
Suppress the fork's ADA-79 retry banner for Claude interrupted-turn diagnostics so users are not
encouraged to resend an already delivered steer.

The provenance verdict is accepted as the scope boundary: message delivery/steering already works;
this change does not add queueing, retry, deduplication, or crash-recovery machinery.

## Blast radius

- `apps/server/src/provider/Layers/ClaudeAdapter.ts`
  - Extend `isInterruptedResult` only.
  - Downstream behavior affected through the existing `turnStatusFromResult` and
    `handleResultMessage` path: steer-abort results must not emit `runtime.error`, must not write
    `session.lastError`, and must complete the turn as `interrupted` instead of `failed`.
  - No provider protocol, persistence schema, turn-delivery, or session lifecycle changes.

- `apps/server/src/provider/Layers/ClaudeAdapter.test.ts`
  - Add a red-first fixture for the exact `[ede_diagnostic]` user-steer result.
  - Add/retain a nearby negative-control fixture showing a genuine execution error still emits
    `runtime.error`, completes `failed`, and records `session.lastError`.

- `packages/client-runtime/src/errors/transport.ts`
  - Add a conservative user-steer diagnostic predicate requiring the complete known
    `[ede_diagnostic]` + `result_type=user` shape, and return `null` for that predicate before the
    broader ADA-79 interrupted-turn friendly-copy mapping.
  - Preserve the existing behavior for transport errors, explicit user aborts, broader interrupted
    diagnostics, and unrelated errors.
  - No web component changes: existing consumers already treat `null` as no banner.

- `packages/client-runtime/src/errors/transport.test.ts`
  - Require no banner for the complete user-steer diagnostic, add near-miss coverage for
    `[ede_diagnostic]` without `result_type=user`, and retain the existing mappings for other exact
    interrupted variants and unrelated errors.

- Runtime/UI verification
  - Rebuild desktop artifacts, drive a real Claude turn through a disposable ephemeral T3 server,
    send a second message mid-turn, and assert delivery, continued work, non-failed completion, and
    absence of the error banner.
  - The live server is explicitly out of scope and will not be restarted or modified.

## Edge-case matrix

| Case                                                | SDK result / client input                                                                                                 | Expected result                                                                                           |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| User steer at tool boundary                         | `error_during_execution`, `is_error=false`, error contains `[ede_diagnostic]`, `result_type=user`, `stop_reason=tool_use` | Server completes `interrupted`; no `runtime.error`; no `session.lastError`; client shows no banner        |
| User steer aborted-streaming variant                | Same subtype/flag and diagnostic with `result_type=user`, plus the known aborted/turn-aborted marker                      | Same clean interrupted classification and no banner                                                       |
| Marker order/case varies within one diagnostic line | All required diagnostic tokens remain present                                                                             | Match without depending on token order or case                                                            |
| Diagnostic marker without `result_type=user`        | `[ede_diagnostic]` describes another result type                                                                          | Server remains failed; client does not suppress it                                                        |
| `result_type=user` without diagnostic marker        | Ordinary execution error happens to mention a user                                                                        | Remains failed                                                                                            |
| Diagnostic on a successful result                   | `subtype=success`                                                                                                         | Remains completed through the existing success path                                                       |
| Diagnostic with `is_error=true`                     | Genuine SDK error result                                                                                                  | Remains failed                                                                                            |
| Generic execution failure                           | `error_during_execution`, `is_error=true` or ordinary error text                                                          | Emits `runtime.error`, completes `failed`, records `session.lastError`, and remains visible to the client |
| Existing explicit abort                             | `Error: Request was aborted.`                                                                                             | Retains the existing server interrupted classification and ADA-79 client copy                             |
| Transport failure                                   | Socket/ping patterns                                                                                                      | Continues to sanitize to `null` via the existing transport path                                           |
| Unrelated business error                            | e.g. missing credentials or invalid selection                                                                             | Preserved verbatim                                                                                        |
| Old server / new client                             | Raw known Claude interrupt diagnostic reaches sanitizer                                                                   | Hidden, preventing unsafe duplicate-send advice                                                           |
| New server / old client                             | Server sends an interrupted turn without runtime/session failure state                                                    | No failed state; old client has no new contract to decode                                                 |

## Red-first test plan

1. Server guardrail on old code:
   - Emit a result fixture matching the observed SDK shape:
     `subtype=error_during_execution`, `is_error=false`, and
     `[ede_diagnostic] result_type=user ... stop_reason=tool_use`.
   - Assert the event sequence contains no `runtime.error`, `turn.completed.state` is
     `interrupted`, and `adapter.listSessions()` has no `lastError`.
   - Expected RED on old code: it emits `runtime.error`, reports `failed`, and records the
     diagnostic as `lastError`.

2. Server negative control on old and fixed code:
   - Emit a genuine `error_during_execution` result whose error is an ordinary execution failure.
   - Assert `runtime.error`, failed completion, and persisted `lastError` remain unchanged.

3. Client guardrail on old code:
   - Pass the observed `[ede_diagnostic] result_type=user ... stop_reason=tool_use` string to
     `sanitizeThreadErrorMessage`.
   - Assert `null`.
   - Expected RED on old code: it returns
     `The turn was interrupted. Send your message again to retry.`
   - Add a negative control where `[ede_diagnostic]` has the same abort marker but lacks
     `result_type=user`; it must not take the new suppression branch.

4. Run the two affected suites after the RED evidence, implement the minimal classifier/sanitizer
   edits, then rerun until green:
   - `vp test apps/server/src/provider/Layers/ClaudeAdapter.test.ts`
   - `vp test packages/client-runtime/src/errors/transport.test.ts`

5. Required repository verification:
   - `vp check`
   - `vp run typecheck`
   - Relevant targeted tests above, then the factory gate on each commit.

6. Fresh E2E verification after `vp run build:desktop`:
   - A new `gpt-5.4-mini` verification worker follows `t3-e2e-testing` against instance
     `ada-111-verify`.
   - It starts a real Claude turn, sends a mid-turn message while work is in progress, and captures
     UI/server/projection evidence that the message is delivered, work continues, the turn is not
     failed, and no retry/error banner appears.
   - It performs one surrounding regression check and tears the instance down.

## Smallest-change argument

The bug is a classification mismatch at an existing result boundary, not a delivery defect. One
conservative predicate extension in `isInterruptedResult` reuses all existing clean-interruption
control flow and automatically avoids `runtime.error` and failed-session state. One narrowly scoped
client predicate plus an early `null` return removes unsafe retry guidance only for the complete
user-steer shape, without changing UI components or contracts. Tests cover both exact positive
shapes and marker/result-type near misses. Queueing, resend, deduplication, persistence, and
crash-recovery changes would enlarge the blast radius without addressing this symptom more directly.
