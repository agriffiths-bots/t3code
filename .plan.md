# ADA-119 plan: lifecycle-owned worktree teardown

## Intent

Promote the gate-clean lifecycle teardown from `a7f6bfc6e` onto current
`origin/main`. Replace the periodic stale-worktree reaper with teardown in the
existing drainable thread lifecycle worker. For a delete, or for an archive
whose provider session has become terminal, the worker sequentially stops the
runtime, closes the thread terminals, removes only an explicit ADA-40-owned
unshared worktree root, prunes its Git registration, and clears ownership
metadata last.

An archive remains reversible. ADA-100's current-event check stays ahead of
archive side effects, so a queued/replayed archive that was superseded by
unarchive does nothing. A completed archive teardown clears the removed
worktree metadata; a later unarchive restores the thread as an active thread in
its project workspace rather than retaining a dead cwd. A standalone stopped or
error session remains resumable and does not remove an unarchived worktree.

## Integration boundaries

- Extend `ThreadDeletionReactor` without replacing ADA-100's archive replay,
  snapshot retry, provider-stop projection, descendant cleanup, or terminal
  cleanup. Delete retains its stop/close order. Archive cleanup validates that
  the event's `archivedAt` is still current before any teardown; terminal
  projection state requests provider stop and remains on the bounded lifecycle
  retry path until a stopped/error event arrives before filesystem teardown,
  using a fresh stop command identity per attempt even when no runtime is
  currently listed; an already-projected error is terminal when no runtime
  remains. Later
  `thread.session-set` events only retry teardown when the current projection is
  still archived or deleted, and a deleted owner still closes terminal history.
  Teardown then re-reads actual provider sessions so an old terminal event
  cannot remove a newly resumed worktree.
- Add one process-wide worktree-lifecycle coordinator. Archive, delete,
  unarchive, bootstrap worktree preparation/final turn dispatch, ordinary
  turn-start dispatch, and the provider reactor's actual
  session-start/send critical section use the same permit. Project creation,
  deletion, and `project.meta.update` workspace-root retargets also use it, so
  teardown's protected-project overlap snapshot cannot become stale before a
  force delete. Worktree/branch-affecting `thread.meta.update` commands and the
  provider's forked first-turn branch rename use the permit too, with current
  owner/path revalidation. Teardown holds the permit across its final
  projection/runtime and project-root revalidation, stop/close, Git inspection,
  removal, prune, and metadata clear. Provider activation re-reads the thread
  after acquiring the permit; teardown that wins prevents a provider from
  starting in a removed cwd, while activation that wins publishes a runtime
  visible to teardown before releasing the permit. Trusted teardown and branch
  metadata dispatches use an already-coordinated path to avoid self-deadlock.
- Put delete confirmation at the shared web deletion boundary so every UI
  caller warns before an owned worktree can be force-removed. Multi-select
  deletion uses one aggregate warning that names every owned worktree, then
  marks the per-thread calls as already confirmed; archived-thread callers pass
  their snapshot metadata into the same boundary because archived rows are not
  present in the live entity store. After every confirmation await, re-read the
  live row and require a new warning if ownership changed; aggregate callers
  pass the exact confirmed owned path rather than a boolean bypass. The shared
  action returns an explicit deleted/cancelled success result so a batch stops
  on a second-dialog cancellation and only clears selections already deleted.
- Keep ADA-124 dispatch-lease release in its existing lifecycle owner. ADA-119
  consumes the same stopped/error/deleted events but does not release leases or
  synthesize duplicate terminal state.
- Removal authorization requires `worktreeRemovable: true` and an absolute
  `worktreeRemovalPath` (falling back only to the same persisted owned
  `worktreePath`). Reject the filesystem root, the owning project root or an
  ancestor, every other project-root overlap, and every root shared with a
  different thread. Every remaining `worktreePath`/`worktreeRemovalPath`
  reference blocks removal even when that consumer is archived or terminal;
  caller-supplied/shared worktrees remain and their archive can still be
  reversed without a dead cwd. ADA-126 remains the separate future path for
  atomically releasing multiple consumers rather than weakening this guard.
- A project workspace-root retarget is rejected while any thread in that
  project retains explicit removable ownership metadata. This preserves the
  repository through which the worktree was created for later removal/pruning;
  the user can first delete/archive and complete teardown (or explicitly retain
  the checkout) before retargeting. Title/script-only project metadata changes
  remain allowed under the permit.
- Stop the provider and close terminals before removal. Non-interruption
  stop/close failures are no longer swallowed on the destructive path. First
  list actual provider runtimes; an absent runtime/binding is already stopped,
  while a present runtime is stopped strictly and the runtime list is rechecked.
  Any remaining runtime or real stop/close failure fails closed before Git and
  enters the lifecycle retry. Immediately before an archive removal, read local
  Git status under the permit. Dirty/untracked work, or a status read that cannot
  establish cleanliness, retains the root and metadata and alarms; archive uses
  non-force removal as a second guard. Only an explicit delete uses
  `force: true`.
- Run removal through the owning project's repository. If the path is already
  absent/ENOENT, log debug and treat physical removal as complete. In both the
  normal and already-absent cases, run Git worktree pruning when the owning
  repository still exists. If both the owned path and owning repository are
  absent, or the owning root is no longer a Git repository, pruning is
  impossible and metadata clears after that state is verified. Only then
  dispatch the metadata clear. A non-absence removal, prune, or metadata-clear
  failure is retried by the same lifecycle worker with a bounded delayed policy
  (five attempts at 250 ms); exhaustion emits a high-signal alarm and retains
  the remaining metadata. A removal that succeeded before a later failure is
  idempotently observed as absent on retry, then pruned and cleared.
- Use deterministic metadata-clear command IDs so duplicate lifecycle events
  and replays are idempotent. Clearing `worktreePath`, `worktreeRemovable`, and
  `worktreeRemovalPath` is the final step and only affects the explicit owner.
- Replay persisted `thread.deleted` as well as `thread.archived` events at
  startup through the same deduplicating lifecycle worker. Already-cleared rows
  are no-ops; committed deletes interrupted before removal resume safely. This
  includes ADA-125's narrow recovery requirement because removing the only
  residual reaper without it would leave a permanent leak.
- Keep checkpoint-ref pruning in `VcsMaintenanceReactor`; delete its stale-row
  selection, physical worktree removal, metadata mutation, and scheduled Git
  worktree sweep. Any retained residual observation may only alarm.
- Remove the web client's competing post-delete `vcsRemoveWorktree` call while
  retaining path display and the existing destructive confirmation. The server
  lifecycle becomes the sole cleanup owner.

## Guardrails (RED on old code)

1. Deleting an explicit unshared owned worktree removes it during the drained
   lifecycle job and clears its metadata only after removal/prune.
2. A shared or nested consumer prevents physical removal and metadata clearing.
3. A worktree directory removed before the lifecycle event is accepted as
   already torn down; its stale Git registration is pruned and metadata clears
   without surfacing an error.
4. Archiving an owned root with no live session removes it; a live archive waits
   for stopped/error. Dirty archive state is retained. An unarchive that
   supersedes queued archive cleanup keeps the worktree and restores the active
   thread state, and a permit-controlled activation race cannot start a provider
   in a removed cwd.
5. Stopped/error on an unarchived thread never removes its worktree; a stale
   terminal event cannot remove a currently live archived/unarchived consumer.
6. Existing/caller-supplied worktrees, project roots, cross-project roots,
   malformed paths, and runtime-scan failures fail closed.
7. Worktree metadata/branch updates serialize with teardown; a workspace-root
   retarget is rejected while the project still owns a removable root.
8. Persisted delete replay completes an interrupted delete after restart without
   double-removing an already-cleared/absent root.
9. Stop/terminal-close and removal/prune/metadata failures retry in the
   lifecycle worker; terminal cleanup failure never reaches filesystem removal.
10. Checkpoint pruning still runs, while no periodic stale-worktree reaper or
    physical worktree sweep remains.
11. ADA-100 archive cascade/replay tests and ADA-124 dispatch-lease release tests
    stay green alongside the lifecycle teardown suite.

## Smallest-change argument

This reuses the reference worker, current projection metadata, existing Git
workflow operations, and current ADA-100 cleanup/replay machinery. It adds no
new ownership database, scheduler, protocol, or restoration subsystem. The only
new Git primitive is explicit registration pruning after lifecycle removal or
an already-absent root. Atomic shared-terminal metadata release remains ADA-126;
until that lands, every other persisted consumer is a hard removal blocker.
