# Persist Factory Reviewer Sessions Plan

## Intent

Add `--persist-sessions` to the factory gate's pinned Codex review arguments so each paid gate review leaves an inspectable rollout with token accounting. Do not change the autoreview helper, gate implementation, application code, or persistence schemas.

## Blast radius

- `scripts/factory/factory.conf`: changes the arguments forwarded by `scripts/factory/precommit-gate.sh` and therefore the reviewer fingerprint/cache identity and audit `args` value.
- Existing helper at `~/.claude/skills/autoreview/scripts/autoreview`: already owns the flag semantics and writes Codex rollouts under `~/.codex/sessions/`; it is consumed, not modified.
- No clients, projections, migrations, restart paths, or runtime services are involved. `.plan.md` is the required planning artifact.

## Edge-case matrix and red-first checks

| Case                                                             | Expected result                                                                                                                                                                                                          | Named red-first check                                             |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Gate before config lands, then after it lands (both orderings)   | The config-changing commit is judged by protected `HEAD`; the first subsequent reviewed staged tree uses the new flag.                                                                                                   | `pre-land negative control` / `post-land persisted-rollout smoke` |
| Duplicate/replayed gate for the same staged tree                 | A cached pass does not pay for or create a second reviewer rollout.                                                                                                                                                      | `cached replay creates no rollout`                                |
| Review process crashes between rollout creation and clean report | Existing gate remains fail-closed; no pass is inferred from a partial rollout.                                                                                                                                           | `clean structured report remains mandatory`                       |
| Multiple rollouts share the same timestamp                       | Attribute evidence by baseline/new path set and JSON payload, not timestamp ordering alone.                                                                                                                              | `rollout set-difference attribution`                              |
| Helper/config version skew                                       | Installed helper advertises `--persist-sessions`; resulting `turn_context.payload.model` is `gpt-5.6-sol`.                                                                                                               | `helper capability and pinned-model check`                        |
| Concurrent unrelated Codex sessions                              | From new paths, select the rollout whose `session_meta` has this exact worktree cwd, `originator=codex_exec`, `source=exec`, and whose user message contains the helper's senior-reviewer prompt; ignore other sessions. | `gate-metadata and prompt attribution check`                      |
| Reviewer override is active                                      | Verification must stop because the approved override replaces the pinned Codex args.                                                                                                                                     | `reviewer override absence check`                                 |

## Verification and smallest-change argument

Before editing config, the exact-flag check is red. After the one-line edit, run the required `vp check` and `vp run typecheck`, commit through the factory gate, then force one transient staged post-commit review so the protected gate loads the newly landed config. Select a new rollout by the exact worktree/originator/source metadata and senior-reviewer prompt above; only then require `turn_context.payload.model == "gpt-5.6-sol"` and an `event_msg` whose `payload.type == "token_count"`, and discard the transient staging. One declarative argument is sufficient because the helper capability and its tests are already proven; duplicating helper logic or adding a gate/parser change would expand the blast radius without improving the requested instrumentation.
