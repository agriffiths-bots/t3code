## 1. INTENT

Fix Cursor/Composer streamed assistant text loss by making buffered assistant deltas survive Cursor completion races where deltas arrive after `turn.completed`, and by draining Cursor ACP session events before the adapter clears the active turn. Keep Cursor plan/tool/user-input events scoped to the active turn so mid-turn Composer updates remain inside the same work block.

Also document the Composer 2.5 context-window state: the shared runtime and projection already support `thread.token-usage.updated`, but Cursor ACP stream handling currently has no parsed usage event source.

## 5. SMALLEST-CHANGE ARGUMENT

The minimal behavioral change is in the shared ingestion boundary where buffered assistant deltas are already aggregated and finalized. A late delta for an explicitly completed turn is terminal data; projecting and completing it immediately fixes the dropped-text class without inventing Cursor-specific persistence or changing the DB schema.

The Cursor adapter change is limited to turn settling: drain queued ACP events before clearing the active turn and emitting completion. I am deliberately not changing the web renderer, not adding migrations, not fabricating context-window usage without a Cursor ACP source, and not rewriting ACP session segment state unless the red-first tests prove the queue barrier is insufficient.
