# PR 216 Reaper and ACP Alias Follow-ups Plan

## Intent

Address all four round-two Codex findings without changing the watchdog thresholds or ACP public API: force-failure projection writes must act only on the same terminal runtime binding observed for the stale turn, and peer-chosen ACP request IDs must be translated symmetrically through requests, control messages, replies, and JSON-RPC batch bookkeeping. Keep the changes local to `ProviderSessionReaper` and the patched ACP transport, with focused regressions proving each reported race and hang.

## Blast Radius

- `apps/server/src/provider/Layers/ProviderSessionReaper.ts`: consecutive cleanup-no-op identity, forced failure dispatch/release fencing, terminal versus non-terminal binding classification, and the direct inactivity `stopSession` class-sweep path.
- `apps/server/src/provider/Layers/ProviderSessionReaper.test.ts`: deterministic replacement-between-reads, waiting/starting/running recovery, turn-identity movement, and stale inactivity snapshot regressions.
- `apps/server/src/provider/Layers/ProviderService.ts`, `apps/server/src/provider/Services/ProviderService.ts`, and `ProviderService.test.ts`: ordinary failure/retry-release callbacks already execute under `stopFailedSession`'s per-thread ownership lock; add narrow internal inactive-stop and stale-force-failure operations so the class-sweep paths re-check their exact binding and serialize every side effect under that same lock.
- `apps/server/src/persistence/ProviderSessionRuntime.ts`, `ProviderSessionDirectory.ts`, projection shell readers, pending-approval resolution, server startup/restart reaper activation, and provider adapters are consumers of the existing binding/projection shapes; no schema, migration, event, or restart protocol change is intended.
- `packages/effect-acp/src/protocol.ts`: raw correlation-ID type capture, pre-parser alias allocation, forward/reverse alias lifetime, `Ack`/`Interrupt` routing, response encoding, alias cleanup, and the vendored Effect `ndJsonRpc` parser's private batch map.
- `packages/effect-acp/src/protocol.test.ts`: string and numeric-looking follow-up controls, mixed and concurrent batch completion, same-text typed IDs, alias cleanup/replay, chunks, and wire-type preservation.
- `packages/effect-acp/src/client.ts`, `agent.ts`, Grok/Cursor ACP adapters, and generated ACP RPC handlers consume the transport unchanged. No generated schema, public contract, persistence, migration, or client UI change is intended.

## Class Sweep

All reaper side effects were enumerated. `failActiveTurn`'s normal `markTurnFailed`, stopped projection, and terminal retry-release projection run as `onOwned`/`onStopped` callbacks inside `ProviderService.stopFailedSession`'s per-thread lock and therefore already share its ownership/turn check; the force fallback now repeats that pattern through a narrow exact-binding/turn operation, with its projection and release callbacks inside the same lock. The unrelated inactivity `providerService.stopSession` call has no ownership parameter, so the reaper instead calls a second narrow internal operation that locks the thread, compares `lastSeenAt` and the complete expected binding, and performs the stop before replacement starts or runtime-state persistence can acquire that lock.

All ACP correlation sites were enumerated: request ingress, raw ID type capture, `Ack`/`Interrupt` ingress, `Chunk`/`Exit` egress, active-ID cleanup, and `ndJsonRpc` batch lookup. Core aliases are allocated in the complete raw frame before `parser.decode`, so every parser batch key is already unique even when raw IDs differ only by JSON type; the typed reverse map routes controls, and emitted response frames restore directly from the exact internal alias without global or cross-batch pending state.

## Smallest Change

Add small local binding-identity helpers for forced failure, plus two optional internal `ProviderService` methods that accept the existing directory snapshots and validate either the forced callbacks or inactive stop under the existing thread lock; do not change persistence schemas or public transport contracts. Replace the one-way ACP alias map with paired typed lookups, pre-parser aliasing of core request IDs, and direct wire restoration of emitted internal aliases; do not fork or modify vendored Effect serialization and do not change ACP schemas or generated RPC code.
